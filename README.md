# 北上广深租房数据分析

本项目基于12,000条北上广深租房样本，使用Pandas完成数据质量检查、数据清洗和描述性分析，使用Matplotlib与Seaborn进行可视化，并通过DuckDB SQL复现和验证核心业务结果。清洗后保留11,978条住宅租房记录。

## 项目目标

本项目围绕当前租房样本回答以下问题：

- 北京、上海、广州和深圳的典型整租租金有何差异？
- 各城市哪些行政区的整租月租金和每平方米租金较高？
- 整租面积、卧室数量与月租金之间存在怎样的关系？
- 在5,000元/月预算下，哪些城市和行政区的可选整租房源更多？

## 数据范围

| 项目 | 内容 |
| --- | --- |
| 城市范围 | 北京、上海、广州、深圳 |
| 原始数据 | 12,000条租房记录，20个字段 |
| 清洗数据 | 11,978条住宅租房记录，26个字段 |
| 出租类型 | 整租、合租 |
| 租金单位 | 元/月 |
| 主要分析范围 | 城市、行政区、面积、卧室数量及5,000元预算 |

## 数据处理方法

- 保留原始面积和租金字段，新增可计算的数值字段。
- 将面积与租金区间转换为区间中点。
- 排除22条经过字段和标题共同确认的非住宅记录。
- 卧室数量缺失不填充为0。
- 保留并使用三类既有异常标记，不未经检查直接删除可疑记录。
- 新增每平方米租金字段，用于补充比较不同面积房源。
- 整租与合租分别分析，典型租金主要使用中位数。

## 核心分析结论

### 城市整租价格

| 城市 | 月租金中位数 | 每平方米租金中位数 |
| --- | ---: | ---: |
| 北京 | 6,500元/月 | 93.02元/平方米 |
| 上海 | 6,000元/月 | 80.88元/平方米 |
| 深圳 | 4,500元/月 | 85.03元/平方米 |
| 广州 | 3,100元/月 | 47.13元/平方米 |

- 北京的整租月租金中位数和每平方米租金中位数均为四个城市最高。
- 深圳的典型整租面积较小，但每平方米租金中位数高于上海。
- 平均数仅作为补充，以降低少数高价房源对典型水平判断的影响。

### 行政区整租价格

行政区价格排名仅纳入整租样本不少于30条的行政区。该门槛只用于限制排名资格，不删除原始记录。

| 城市 | 月租金中位数最高行政区 | 月租金中位数 | 每平方米租金最高行政区 | 每平方米租金中位数 |
| --- | --- | ---: | --- | ---: |
| 上海 | 静安 | 13,000元/月 | 静安 | 153.06元/平方米 |
| 北京 | 海淀 | 8,200元/月 | 东城 | 129.17元/平方米 |
| 广州 | 越秀 | 4,500元/月 | 越秀 | 75.00元/平方米 |
| 深圳 | 南山区 | 8,500元/月 | 南山区 | 121.67元/平方米 |

北京的月租金与每平方米租金排名结果存在差异，说明总租金会受到房屋面积影响。

### 面积与月租金关系

- 关系分析使用11,526条整租房源，不包含38条带有既有异常标记的记录。
- 整租面积与月租金的总体皮尔逊相关系数约为0.707，呈较明显的正相关。
- 四个城市内部的相关系数均为正数，范围约为0.655至0.743。
- 相关关系只能描述变量之间的线性联系，不能证明面积增加会单独导致租金上涨。

### 卧室数量与月租金

| 卧室数量 | 整租房源数量 | 月租金中位数 |
| ---: | ---: | ---: |
| 1室 | 3,540 | 3,200元/月 |
| 2室 | 4,004 | 5,200元/月 |
| 3室 | 2,904 | 6,200元/月 |
| 4室 | 781 | 12,000元/月 |
| 5室 | 221 | 17,000元/月 |

- 在1至5室的正式比较范围内，卧室数量增加时，典型月租金总体上升。
- 6室及以上房源的组内样本明显减少，因此不用于主要租金差异结论。
- 卧室数量缺失的记录继续保持缺失，没有填充为0。

### 5,000元预算分析

预算分析使用11,526条整租房源，其中5,895条月租金不超过5,000元，总体占比为51.15%。

| 城市 | 预算分析房源数量 | 预算内房源数量 | 预算内占比 |
| --- | ---: | ---: | ---: |
| 广州 | 2,874 | 2,329 | 81.04% |
| 深圳 | 2,670 | 1,493 | 55.92% |
| 上海 | 2,991 | 1,212 | 40.52% |
| 北京 | 2,991 | 861 | 28.79% |

各城市预算内整租房源数量最多的行政区：

| 城市 | 行政区 | 预算内房源数量 |
| --- | --- | ---: |
| 上海 | 浦东 | 302 |
| 北京 | 通州 | 140 |
| 广州 | 白云 | 578 |
| 深圳 | 宝安区 | 463 |

广州在当前样本中的预算内房源数量和覆盖比例均为四个城市最高；广州白云是四个城市中预算内整租房源数量最多的行政区。

## SQL复现与验证

项目使用DuckDB 1.5.5建立内存连接，直接读取清洗CSV，没有生成本地数据库文件。

三个正式SQL文件分别用于：

- `01_data_validation.sql`：验证数据规模、城市分布、出租类型和异常标记。
- `02_market_analysis.sql`：计算城市整租租金、每平方米租金及面积相关系数。
- `03_budget_analysis.sql`：完成5,000元预算分析及城市内部行政区排名。

SQL分析使用了聚合函数、条件筛选、CTE、`CORR`相关系数、窗口函数和多字段排序。核心统计由SQL完成，Pandas只用于显示结果和与既有结论交叉核对。SQL结果与此前验证的Pandas结果一致。

## 运行方法

克隆仓库并进入项目目录：

```powershell
git clone https://github.com/Danyu0507/China-rent-analysis.git
cd China-rent-analysis
```

创建并激活Python虚拟环境：

```powershell
py -m venv .venv
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

安装项目依赖并启动JupyterLab：

```powershell
python -m pip install -r requirements.txt
jupyter lab
```

项目未在GitHub中提交CSV文件。完整运行前，需要将原始数据保存为：

```text
data/raw/data_sample.csv
```

随后按照编号运行Notebook。`03_data_cleaning.ipynb`会生成：

```text
data/processed/rent_cleaned.csv
```

该清洗文件供后续分析Notebook和DuckDB SQL分析使用。

## 数据限制

- 本项目使用固定租房样本，分析结果不代表租房平台的实时全部市场供应。
- 整租与合租分别分析，不将两类房源直接混合比较。
- 北京没有合租样本，上海仅有3条合租样本，合租样本的城市分布严重不均衡。
- 合租记录中的卧室数量和面积字段含义可能不统一，因此合租面积、每平方米租金和卧室结构不用于城市市场排名。
- 可疑记录保留既有异常标记，并根据具体业务问题确定分析范围，不直接修改或删除原始记录。
- 所有结论仅描述当前数据样本，不应解释为因果关系或实时市场规律。
